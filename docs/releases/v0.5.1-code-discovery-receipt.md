## Target and base decision

Target: strengthen the existing Brief2Ship CLI's repo-first decision quality, network/sandbox safety, packaging trust, and automation behavior while preserving Python 3.11+, zero core runtime dependencies, bounded receipts, and default prohibition on candidate execution.

This was a substantial patch inside the already-canonical repository, so the new-build discovery preflight exception applied. Disposition: `selective-reuse` of the existing canonical Brief2Ship architecture; no new framework or dependency base was introduced.

## Repo-first skill steps confirmed

The operator's repo-first additions were present before this audit in `skills/brief2ship/SKILL.md:51-78`, introduced by `d89c1b8`:

- compare at least 2–3 real candidates for non-trivial spaces;
- inspect license, maintenance, fit, adaptation cost, and risk;
- run bounded `brief2ship discover` across selected ecosystems;
- score feature fit, activity, dependencies, security/OSV, tests, portability, reuse readiness, and adoption;
- inspect manifests, dependencies, tests, CI, docs, examples, source footprint, and commit;
- record exactly `fork`, `use-as-library`, `selective-reuse`, `reject`, or `build-clean`;
- never execute candidate code by default; explicit tests require the Bubblewrap gate.

These rules were preserved and their sandbox wording was tightened.

## Audit findings and dispositions

| Severity | Finding at `d89c1b8` | v0.5.1 disposition |
|---|---|---|
| High | URL validation and `urllib` connection performed separate DNS resolution; environment proxies could bypass direct target validation | Fixed: each default connection uses revalidated, pinned socket addresses; environment HTTP(S) proxies are disabled; original host remains the HTTP Host / TLS SNI identity |
| High | Bubblewrap had a host-backed writable worktree; an untrusted test could exhaust disk/inodes | Fixed: candidate, `/work`, `/tmp`, `/home`, and root are read-only; additional-process allowance reduced; per-process address space reduced to 512 MiB; sandbox receipt bumped to `brief2ship-bwrap-v2` |
| High | `setuptools>=68` could not parse the declared SPDX `project.license = "MIT"` metadata | Fixed: build backend floor is `setuptools>=77`; exact floor build passed |
| Medium | `--limit` truncated candidates before `--inspect-top`, preventing requested inspections and possible reranking | Fixed: inspection runs against the full bounded candidate set, then final output applies `--limit` |
| Medium | Scarce inspection slots were allocated by overall score, allowing popularity/metadata to crowd out direct feature fit | Fixed: inspection shortlist prioritizes feature match, then total score |
| Medium | Long target sentences produced zero GitHub results | Fixed: one deterministic, receipt-visible, maximum-three-term focus fallback runs only after zero results |
| Medium | PyPI equal-fit names were reverse-alphabetical | Fixed: deterministic ascending lexical tie-break |
| Medium | Candidate disposition emitted undocumented `clean-build`, while run-level/docs used `build-clean` | Fixed: canonicalized on `build-clean` |
| Medium | Missing license/security blockers could still emit clean-build when total score was low | Fixed: blockers now return `reject` before score threshold handling |
| Medium | Deduplication mutated provider-owned candidate objects and compared offset timestamps lexically | Fixed: dedup starts from copies and compares timestamps chronologically |
| Medium | A blocking read that returned late with an empty body could pass the wall-clock deadline | Fixed in scraping and discovery HTTP clients; DNS validation is also included in the fetch deadline |
| Medium | ALM/LRM/RLM bidi controls survived extraction/human-readable receipt sanitization | Fixed alongside the existing embedding/isolate control filter |
| Medium | A crawl with both successful pages and failures exited `0` | Fixed: manifest remains written, but partial crawl exits `4` |
| Low | `python -m brief2ship` was unavailable | Fixed and added to release/CI gates |
| Low | Unicode receipt output could fail under inherited ASCII stdio | Fixed by reconfiguring real CLI stdout/stderr to UTF-8 |
| Low | Top-level and doctor help under-described repo-first discovery | Fixed |
| Low | Docs validation silently skipped a missing declared receipt even in a Git checkout | Fixed: Git checkouts require receipts; extracted sdists intentionally skip source-only receipts |

## Known limitations / next release gate

1. Do not call v0.5.1 public until the branch is reviewed, merged, pushed, CI passes on Ubuntu/Windows with Python 3.11/3.12, and the tag/raw skill URLs are read back.
2. The read-only sandbox intentionally causes tests needing build artifacts, caches, or temporary files to fail conservatively.
3. Callers injecting a custom HTTP opener own equivalent DNS pinning and proxy controls.
4. The GitHub focus fallback is lexical, bounded, and explainable—not semantic search. Human inspection remains mandatory.
5. Old v0.4/v0.5 build archives remain tracked in Git; future artifacts should be release assets rather than new committed binaries.
6. No PyPI publication is part of this candidate.
7. The installed machine-wide/local CLI and profile skill were not replaced during this audit.
