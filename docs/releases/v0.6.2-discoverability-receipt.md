An initial extracted-sdist run exposed two packaging defects: the pull-request template was omitted from `MANIFEST.in`, and a case-study link targeted a release receipt intentionally excluded from packages. Both were corrected. A later independent blocker review found that wildcard release-asset patterns could admit extra distributions not covered by `SHA256SUMS`. The workflow now derives two exact filenames from `VERSION`, requires the release directory and checksum file to contain exactly those two distributions, runs Twine before the final integrity verifier, and uploads only those exact paths. The rebuilt extracted sdist passed all 145 tests.

## PyPI

Trusted Publishing workflow source is included. It is deliberately manual-only and refuses non-tag refs, preventing an unconfigured pending publisher from turning the GitHub release into a false failed-publish signal. Source validation and exact GitHub-release asset checksum verification occur in a separate read-only job; only the two-step artifact-download/publish job receives `id-token: write`. The workflow publishes the same tested wheel and sdist attached to the GitHub release rather than rebuilding timestamp-varying archives. Publication requires the PyPI project or pending publisher to trust:

```text
owner: five0nit
repository: brief2ship
workflow: publish-pypi.yml
environment: pypi
```

Publication status: pending authentication/configuration and exact-tag release.
