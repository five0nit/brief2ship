# Brief2Ship v0.5 Code Discovery Implementation Plan

**Goal:** Search five public code/package ecosystems, normalize and inspect candidates, produce explainable /100 rankings, and recommend fork, library, selective reuse, clean build, or rejection before implementation starts.

## Product contract

```bash
brief2ship discover "local web scraper with robots support" \
  --sources github,pypi,npm,crates,huggingface \
  --per-source 10 \
  --limit 10 \
  --inspect-top 3 \
  --output discovery/
```

Optional untrusted test execution requires two explicit flags and a supported local sandbox:

```bash
brief2ship discover "..." --inspect-top 3 --test-top 1 \
  --allow-untrusted-tests --output discovery/
```

## Sources

- GitHub REST repository search; token optional through `GH_TOKEN`/`GITHUB_TOKEN`.
- PyPI official Simple index, streamed and locally cached because PyPI search is protected by a JavaScript client challenge; package details use `/pypi/{name}/json`.
- npm public registry search and package documents.
- crates.io public search and dependency endpoints with a descriptive User-Agent.
- Hugging Face public model, dataset, and Space APIs.
- OSV public query API for package-version vulnerability evidence.

## Scoring /100

- feature match: 25
- maintenance/activity: 15
- dependency weight: 10
- security posture: 15
- test quality: 10
- portability: 10
- reuse readiness/difficulty: 10
- adoption/health: 5

Every component must include evidence and unknown-data treatment. Ranking is rerun after static inspection and sandbox receipts.

## Safety

- No paid APIs required.
- No scraping challenge bypass.
- Tokens are optional, domain-scoped, and never rendered.
- Per-source limits, byte caps, total timeouts, and failure receipts.
- Clone only canonical HTTPS GitHub repositories; shallow, no tags.
- Never execute repository code by default.
- Explicit test mode uses Bubblewrap, no network, cleared environment, bounded CPU/memory/process/file/time limits, and no host-home mount.
- Unsupported sandbox means blocked test receipt, never unsafe fallback.
- Output directory must be new or empty.

## Files

- add discovery models, HTTP client, providers, scoring, inspection, orchestration, and render modules under `src/brief2ship/`
- extend `brief2ship discover` CLI
- add provider/scoring/inspection/integration/release tests
- add `docs/code-discovery.md`, examples, changelog, skill guidance, CI gates, and v0.5 receipt
- bump all version surfaces to `0.5.0`

## Gates

1. fixture-based provider tests for every source and partial failures
2. deterministic scoring/recommendation tests
3. static clone inspection and sandbox refusal/pass tests
4. Linux and Windows full suites
5. clean wheel/sdist install and installed `discover` round trip
6. bounded live search across all five ecosystems
7. secret scan, Ruff, Pyright, package audit, docs contract, diff check
8. commit only after every invalidated gate is rerun
